# Adding things to Bodylang

This page lists, for each kind of thing you can add, the steps that no compiler or test asks for. [`AGENTS.md`](../AGENTS.md) has the rules and commands that apply to all work here.

Add the name to its list, run `pnpm exec tsc --noEmit`, and fill in what the compiler asks for. Then do these steps, which nothing checks. A new preset, reading, curve, built-in line or organ moves the golden test, which hashes those lists, so regenerate it last and read the diff, as "Checking what you changed" in `AGENTS.md` says.

- **Event preset** (`PRESETS` in `src/model/events/types.ts`): its numbers go in a block in `src/model/params.ts`, each with its source and evidence grade. Name it in the list under "What happened, and which tool records it" in `SYSTEM_PROMPT` in `server/tellPrompt.ts`, and in the `intensity` text and per-preset rules of `log_event` in `src/actions/schemas.ts`. Add a day using it to `SCENARIOS` in `src/model/testScenarios.ts`, and pin its published numbers in `src/model/published.test.ts`.
- **Reading** (`ReadingId` in `src/model/ids.ts`): its spec goes in `src/model/assess/readings/<group>.ts` and its band in `REFERENCE` in `params.ts`. Add it to `readout` in `src/model/readout.ts` if the LLM should state it. A new curve goes in `SERIES` and is written in `recordSeries` in `src/model/engine/simulate.ts`.
- **Process**: prefer one file, `src/model/extensions/<id>.ts`, that exports `extension` per `src/model/extensions/api.ts`, with at least three tests beside it that run the real model through `simulate`. The app finds it by itself, and it can't change a number on screen. `contract.test.ts` in that folder holds a working sample, and `thyroid.ts` there is a real one. A line that runs all day is a `BodyLineId`, and its builder in `src/model/processes/body.ts` must also go in `PROCESS_BUILDERS` in `src/model/processes/processes.ts`.
- **Tool**: one that leaves the day and the view alone is a `tool(...)` entry in `startTurn` in `server/tellTurn.ts`, returning any number the LLM may state through `told`, a helper in that function, or `server/numberCheck.ts` marks the number as invented. One that changes them is an action in `ACTION_SCHEMAS` in `src/actions/schemas.ts`. Say when to use it in that `SYSTEM_PROMPT` list, and test it in `src/actions/reduce.test.ts` and `server/tellTurn.test.ts`.
- **Organ** (`ORGANS` in `src/model/ids.ts`): `src/closeup/organs.test.ts` then wants a close-up. Also add its mesh (`src/scene/anatomy.ts`, `ORGANS` in `pipeline/build_atlas.py`, `public/assets/`), its row in `MESHES` in `server/track.ts` so an injury's path can cross it, its system's `organs` in `SYSTEMS`, the `ORGANS` list in `src/scene/stage.ts`, and its glow in `src/scene/organStates.ts`.
- **Part with no organ, such as a gland**: add it to `ORGANS` in `pipeline/build_atlas.py` and rebuild the assets as `docs/development.md` says, to `PARTS` and `PART_NAMES` in `src/scene/anatomy.ts`, and to `MESHES` in `server/track.ts`. To light it on a page, add it to that page's view's `parts` in `src/scene/stage.ts`, and to `PART_LABELS` there to name it. To make a process stop on it, map the stop's label to it in `GLAND_OF_STOP` in `src/scene/anatomy.ts`.
- **Close-up**: write `src/closeup/<organ>.ts` with `defineCloseup`, each level from 0 to 1 with a meaning in words. Nothing in it draws, because the server loads it to check a walkthrough. Add it to `CLOSEUPS` and `closeupSpec` in `src/closeup/list.ts`, draw it in `src/ui/insets/<Organ>Inset.tsx` from the shared `parts/` with each caption reading its level, and add it to `FIGURES`.
- **Server route, or anything crossing to the browser**: one row in `ROUTES` in `server/routes.ts`, every shape both sides read as a zod schema in `src/wire.ts`, and `BadRequest` thrown for bad input.
